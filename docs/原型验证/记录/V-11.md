## 2. 平台事实（实测，CfT 159 与 Edge 157 分开）

| 事实 | CfT 159 | Edge 157 | 证据 |
| --- | --- | --- | --- |
| 后台里无手势调用 `sidePanel.open` | 拒绝：「may only be called in response to a user gesture」 | 拒绝（快捷键 / 右键用例里记到 `sidepanel/openFailed`） | 探针；`routing.spec.ts`「右键总结本页」 |
| 设置页标签里可信点击，同步 `open({windowId})` | 能打开 | 能打开 | `openPanelByTrustedClick`（所有侧边栏用例的起点） |
| **网页里的点击 → 内容脚本 `runtime.sendMessage` → 后台处理函数第一时间同步 `open`** | **能打开** | **能打开** | 探针 T2；产品路径 `routing.spec.ts`「小窗加载失败…再点「问」由后台同步打开侧边栏」 |
| 同上，但 `open` 之前先 `await`（`storage.session.get`、`tabs.get`） | 拒绝 | 拒绝 | 探针 T3 |
| 同上，`open` 推迟 1.2 秒（`setTimeout`） | 拒绝 | 拒绝 | 探针 T3b |
| 小窗 iframe（扩展页面）里可信点击，同步 `open`，`windowId` 事先用 `tabs.getCurrent()` 取好 | 能打开 | 能打开 | 探针 T4；`handoff.spec.ts` 全部用例 |
| 面板已开时再 `open` | 不重载（`performance.timeOrigin` 不变），不报错 | 未单独测 `timeOrigin`；转接用例里已开的面板再 `open` 后同一面板继续工作 | 探针 P6；`handoff.spec.ts`「侧边栏先打开」 |
| `sidePanel.close({windowId})` | 可以 | 可以 | 探针 T1、T2；V-12 重排用例 |
| 面板自己 `window.close()` | 可以 | 可以 | 开关快捷键用例 |
| `runtime.getContexts` 给侧边栏的 `windowId` | **-1**（全局面板） | **-1** | 探针；`sidepanel.spec.ts`「本窗口授权」日志 |
| 侧边栏端口的 `sender` | 只有 `id`、`url`、`origin`；**没有 `documentId`、`tab`、`frameId`** | 同 | 同上 |
| `sidePanel.onOpened` / `onClosed` | 有，事件带 `windowId` 与 `path` | 未测 | 探针 |
| Playwright 拿侧边栏页面 | `context.pages()` 与 `page` 事件都没有；浏览器级 `Target.getTargets` 能看到，`attachToTarget` 后可求值、可发可信鼠标键盘事件 | 同 | `sidepanel-helpers.ts` |
| Playwright 键盘按扩展快捷键（Alt+Shift+D 等） | 不触发 `commands.onCommand` | 不触发 | 探针 |
| 扩展事件对象自带 `dispatch()`，可在后台直接触发已注册的监听器 | 可以（没有手势） | 可以 | `dispatchCommand` / `dispatchMenu` |

> 结论：任务说明里「网页工具栏点击开不了侧边栏」在 CfT 159 / Edge 157 上**不成立**——只要后台在收到点击消息的同一个同步段里调用 `open`。之前有任何 `await` 就会失败。另有公开报告（crbug 355266358）说个别 Chrome / Brave 版本把消息里的手势当作受限手势，所以打不开时的网页提示保留为退路（V-02）。

### 3.4 开关快捷键（5.4）

| 子项 | 步骤 | 期望 | 实际 | 结论 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 已开的面板收到命令自行关闭 | 后台里直接触发 `toggle-sidepanel`（无手势，`open` 被拒，广播照发） | 面板关 | 关 | 通过 | `sidepanel.spec.ts`「开关快捷键」 |
| 命令之后才打开的面板不受旧命令影响 | 命令记录在 storage.session，之后新开面板 | 不关 | 不关 | 通过 | 同上 |
| 两个窗口只关本窗口的 | 两个窗口各开一个，只在窗口 2 触发 | 只剩窗口 1 的 | 一致 | 通过 | 同上 |
| 快速连按两次（无手势） | 连续触发两次 | 第一次关，第二次不会又开回来 | 一致 | 通过 | 同上 |
| **真实按键：关着时按 → 开；开着时按 → 关；快速连按两次** | 需要真实键盘 | 开 / 关 / 无闪开闪关 | — | **环境阻塞**（Playwright 按不出扩展快捷键）；见手动检查清单 | 第 5 节 |

> 机制：命令处理里先同步 `open`，再把命令时间写进 storage.session 并广播 `sidepanel/toggle`；面板加载时先挂监听再读记录，自己的 `performance.timeOrigin` 早于命令时间就 `window.close()`。这次 `open` 新开的面板创建晚于命令时间，不会关。理论上的漏洞：连按两次间隔短于新面板创建耗时（几十毫秒）时，第二次会被当成「开」吞掉——结果是保持打开，不会闪开闪关。在手动确认之前，需求 J4 不改写，也不对外承诺「一键开关」。
