## 2. 步骤逐项结果

| 步骤 | 做法 | 证据 | 结果 |
| --- | --- | --- | --- |
| URL、main 节点、长度都不变，只换文字 | 网页脚本把一段换成等长文字，`main` 是同一节点（打标记核对），显示文字长度相同 | 第二次请求只含新文字、不含旧文字；`pageKey` 与 `documentId` 不变，`contentVersion` 变了，可提取字数相同；第三次（没再变）阅读器只回 `docUnchanged`（读取结果依次 `parts, parts, unchanged`） | 通过 |
| 选区所在段落被网页改写 | 旧选区还挂在小窗上，网页把那一段整段换掉 | 不按位置猜前后段落：`pageRead: false`，计划注明「没能在页面正文里找到选区」，请求只带选区 | 通过 |
| hash 路由 | `#/a` → `#/b` | `pageKey` 由 `…#/a` 变 `…#/b`，`documentId` 不变，`contentVersion` 变；请求只有视图 B 的正文 | 通过 |
| 查询参数切换 | `pushState` 到 `?tab=1` → `?tab=2` | `pageKey` 跟着变，同一文档；请求只有标签二的正文 | 通过 |
| 只加跟踪参数 | `pushState` 到 `?tab=2&utm_source=x` | `pageKey` 不变、指纹不变，用缓存 | 通过 |
| 前进后退（没用过小窗的页面） | 开启往返缓存，A → B → 后退 | `pageshow.persisted = true`（从往返缓存恢复）；之后提问按 A 的内容读取 | 通过 |
| 前进后退（用过小窗的页面） | A 里提问 → B 里提问 → 后退 | 未进往返缓存，原因 `EmbedderExtensionFrame`、`BrowsingInstanceNotSwapped`；后退后是新文档，按 A 的内容重新读取，指纹与第一次相同 | 通过（性能代价见发现 2） |
| 同一 URL 两个标签页内容不同 | 同一地址返回不同内容，各自提问 | `pageKey` 相同，`documentId` 与指纹不同；各自的请求只含各自的内容；回到第一个标签页再问仍是第一个的内容 | 通过 |
| 在模型回答前导航 | 慢速中转站（3.5 秒才回头），请求发出后立刻导航 | 在途任务照常跑完（规则 2），它的请求与计划仍是导航前的文档与版本；新页面的发问用新文档与新版本，互不混入 | 通过 |
| 旧回答仍归属原版本 | 同上 | 每次请求的计划带着当时的 `documentId + contentVersion` | 通过 |
| 选区属于导航前的文档 | 单测：点「问」后导航再发问 | 不把旧选区套到新文档上，计划注明「选区来自之前打开的页面」 | 通过 |
| 内容变了、选区块号变了 | 单测：新版本前面插入两段 | 用锚点在新版本里重新定位（旧块号 b10 → 新块号 b12），不沿用旧块号 | 通过 |
| 旧总结再次打开、旧总结标注 | — | 总结与历史持久化（IndexedDB）尚未实现 | 未执行 |

## 3. 实测发现

| # | 发现 | 影响 | 处理 |
| --- | --- | --- | --- |
| 1 | Chrome 159 / Edge 157：hash 路由与 `pushState` 之后，内容脚本消息的 `sender.url` 仍是文档创建时的地址，而标签页地址（`tabs.get`）跟着变 | 按 5.6「`pageKey` 由 sender 地址规范化」会把单页应用的不同路由记成同一页 | 地址改取标签页当前地址（浏览器给的，不取自消息，符合规则 7）；读取前后标签页地址必须一致、且与 sender 同源，否则视为读取期间换了页，不用这份正文 |
| 2 | 页面里有扩展 iframe（小窗，包括工具栏出现时预热的隐藏小窗）就不进往返缓存，原因 `EmbedderExtensionFrame` | 正确性不受影响（后退时重新读取）；但用户划过词的页面，后退会整页重新加载，比没装扩展慢（V-13 性能） | 不在本项修。可选退路：页面 `pagehide` 时销毁小窗 iframe（归小窗宿主负责的 agent 评估），或接受此代价并写进 V-13 基线 |
| 3 | 读取时网页上的选区可能已被网页脚本改写（选区修订号没变） | 锚点会指向改写后的内容 | 锚点文字必须包含在点「问」时存下的选区文字里，否则不信锚点 |
