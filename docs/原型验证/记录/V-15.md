## 0. 结论摘要

| 子项 | 结论 | 依据 |
| --- | --- | --- |
| 框选 → 预览 → 发问，请求里带图 | 通过 | e2e 1：请求最后一条用户消息是数组，含 `image_url`（`data:image/png;base64,…`），PNG 宽高 = 框选 CSS 尺寸 × 设备像素比 |
| 坐标正确（100%） | 通过 | e2e 1：框 320×200 的色块，PNG 正好 320×200（DPR 1）；截图目视红蓝分界在正中 |
| 坐标正确（页面缩放 125%） | 通过 | e2e 6：`tabs.setZoom(1.25)` 后框选，PNG 宽高与「页面收到的指针 CSS 坐标差 × devicePixelRatio」相差 ≤ 2 像素；缩略图里红蓝比例与框选范围一致 |
| 坐标换算（DPR 1 / 1.25 / 1.5 / 2、页面缩放 80%、非整数比例） | 通过（单测） | `cropPixels` 按「实际图片尺寸 ÷ 视口」现算，不假定 DPR |
| 不同系统 DPI（真实 125% / 150% 显示缩放） | **环境阻塞** | 本机 CfT 无界面运行，系统缩放无法由脚本切换；手动步骤见第 3 节 |
| 框选后滚动 → 丢弃 | 通过 | e2e 4：拖动中 `scrollBy`，不出预览，网页上出提示 |
| 框选中改页面缩放 → 丢弃 | 通过 | e2e 7：拖动中 `setZoom(1.5)`，不出预览，网页上出提示 |
| 框选中切标签页 → 丢弃 | 通过 | e2e 8：拖动中切到另一标签页，后台记 `capture/failed changed`，没有 `capture/ready` |
| 切窗口 → 丢弃 | 部分通过：单测通过，真实切窗**环境阻塞** | 单测：标签页不是活动页 / 挪到别的窗口 → changed；阅读器在窗口失焦时让修订号加一（实现），无界面 CfT 里窗口焦点不可靠，手动步骤见第 3 节 |
| 侧边栏开合导致重排 → 丢弃 | 部分通过：单测通过，真实侧边栏开合**环境阻塞** | 视口宽度变化 → resize → 修订号加一；截图与视口横纵比例不符 → `mismatch` 丢弃（单测）。Playwright 打不开侧边栏（要用户手势），手动步骤见第 3 节 |
| 文档变了（导航后旧框选的 rect 到达） | 通过（单测） | sender.documentId 与开始时不同 → notOwner，不截图 |
| 遮罩和小窗不进截图 | 通过 | 截图前阅读器隐藏遮罩、把小窗设为不可见、等两帧再应答；e2e 1 的缩略图颜色与页面原色一致（没有遮罩的暗化层）。小窗与框选区域重叠的情况未专门自动化 |
| 取消 | 通过 | e2e 3：Esc 后遮罩撤掉，不出预览、不发请求、storage.session 里没有待确认截图；右键、「取消」按钮同一路径 |
| 预览后明确提交（AR-16） | 通过 | 预览在输入区，发问即确认；× 去掉后发问不带图（e2e 2）；预览提示「请先确认图里没有密码、证件号等敏感内容」 |
| 视觉能力「不支持」 | 通过 | e2e 5：预览里提示换模型；发问被后台拒绝（noVision），模拟中转站 0 次请求；截图保留 |
| 视觉能力「未知」失败时提示 | 通过（实现 + 组件逻辑） | 失败类型为参数被拒 / 响应异常 / 服务端错误等时，回答下提示「可能是当前模型不支持看图」；未单独 e2e |
| E4 图表解析提示 | 通过 | e2e 1：回答下显示「图表解析可能不完全准确，建议核对原图」 |
| 发送说明如实（规则 8） | 通过 | e2e 1：发送说明含「附图 1 张」；计划 `imageCount` 为 1，追问不带图（第二次请求的用户消息是纯文本） |
| 图片获取路径和模型接收方可审查 | 通过 | 图片只来自 `tabs.captureVisibleTab`（5.14 无新请求类别），只发给当前对话所选的模型连接；原图只在后台、storage.session（内存型）、数据库与模型请求里，界面只拿 ≤ 44 KB 的缩略图 |
| 无模型秘密被发给图片域名 | 通过（本次不适用） | 框选截图不访问任何图片地址；页面图片（E2）未实现，不发任何图片请求 |
| 持久化与级联 | 通过（单测） | 发问时原图在接单事务里写进 blobs（refCount 1），用户消息引用它；删除对话时解引用，减到 0 删除（IndexedDB 与内存实现一致） |
| 页面图片：跨源、需登录、很大、不可读 | **未执行** | E2 未实现 |

## 3. 环境阻塞项的手动步骤

| 子项 | 手动步骤 | 期望 |
| --- | --- | --- |
| 系统 DPI 125% / 150% | Windows 设置 → 显示 → 缩放改为 125%（再测 150%）；`pnpm build` 后加载 `.output/chrome-mv3/`；打开任意文章页，按 Alt+Shift+X 框一块有明显边界的区域；发问后在设置页导出诊断或在模拟中转站看请求 | 缩略图边界与所框区域一致，不偏移、不缺边 |
| 真实切窗口 | 开两个浏览器窗口；在窗口 A 按 Alt+Shift+X，按住鼠标拖动时 Alt+Tab 切到窗口 B，再切回松开 | 不出预览，网页上提示「截图前页面发生了变化…」 |
| 侧边栏开合导致重排 | 在页面上按 Alt+Shift+X 开始框选，按住鼠标时用 Alt+Shift+D 打开侧边栏（或从侧边栏的「截图」按钮开始框选后关掉侧边栏），再松开 | 不出预览、提示重新框选；绝不发出与所框区域不符的图 |

## 4. 结论

| 字段 | 内容 |
| --- | --- |
| 结论 | 框选截图部分**通过**；系统 DPI、真实切窗、真实侧边栏开合**环境阻塞**（逻辑由单测覆盖，手动步骤见第 3 节）；页面图片（E2）**未执行**（未实现） |
| 失败退路及其产品代价 | 任何一次核对对不上都丢弃并请用户重选：代价是偶尔要重框一次，换来绝不发错图 |
| 已接受的降级 | 图片只随框选那一轮发送，之后的追问不重发（历史里留一句「本轮附有截图」）；历史回看显示缩略图，原图不进界面 |
| 是否需要修订架构 / 需求 / 最低版本 | 不需要修订最低版本；建议的新决策见本次交付报告（缩略图代替分片传输、画布显示缩略图、待确认截图保管上限等） |
