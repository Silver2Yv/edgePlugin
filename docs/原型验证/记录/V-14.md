## 0. 结论摘要

| 子项 | 结论 | 依据 |
| --- | --- | --- |
| 写失败 | 通过 | `conv-db.test.ts`「同一对话同一序号只能有一条（整个写入失败）」断言事务回滚；`persist-flow.test.ts`「接单写库失败：拒绝（storageFailed），不写 session、不发请求」；`favorites.test.ts`「写库失败时回 ok:false，不广播 favorite/changed」 |
| 空间不足（quota） | **未执行** | 代码把所有数据库写失败统一归为 `storageFailed`，没有区分配额不足与其他写失败原因；没有用例模拟 `QuotaExceededError`，不知道浏览器真实报出配额错误时是否仍落在同一条路径上 |
| 删除对话 | 通过 | `conv-db.test.ts`「删除对话：级联删消息与无人引用的快照，被引用的快照与别的对话不动」；e2e `history-favorites.spec.ts`「历史：能搜到一个对话并删除它」 |
| 删除收藏 | 通过 | `favorites.test.ts`「favorite/remove 删除后解引用快照、blob；再删不存在的收藏回 invalid」 |
| blob 引用清理 | 通过 | `conv-db.test.ts`「消息引用的图片解引用（capture 块），减到 0 的删除，别的对话还在用的留着」；两种实现各跑一次 |
| 快照过期 | 通过 | `conv-db.test.ts`「快照清理：到期且无人引用的删掉；按条件删（不论引用）」；`persist` 报告称启动扫描会清过期且无人引用的快照（未见专门单测名，功能点与清理函数共用同一个 `purgeExpiredSnapshots`） |
| 旧 schema 升级 | **部分通过（机制层面）** | `conv-db.test.ts`「升级失败：整个升级回滚，库停在旧版本、旧数据还在，打开报错；修好后再打开能升上去」「库的版本比代码新（扩展回退）：打开失败并报错，不覆盖」——这是用**合成**的迁移函数测试升级机制本身；本产品数据库版本至今仍是 1（persist 块报告：「之前没有发布过库」），**没有真实发生过一次「旧 schema → 新 schema」的生产升级**，机制可信但未经真实场景检验 |
| 加载解压缩原目录更新 | 未执行 | 需要手动：先加载旧版 `.output/chrome-mv3/` 产生数据，再用新代码覆盖同一目录重新加载，观察数据库是否正常打开。自动化测试环境（Playwright 持久化上下文、每次全新 profile）不模拟这个过程，本轮未做，见第 3 节手动步骤 |
| 扩展重载 | 未执行 | 同上，需要真实浏览器手动操作（`chrome://extensions` 点「重新加载」），验证 Service Worker 重启后数据库连接与在途任务的处理；逻辑上与「跨后台重启」（`persist.spec.ts` 用 CDP `stopAllWorkers` 模拟）同源，但手动重载是另一条路径（扩展进程整体重启，不只是 Service Worker 被回收），未单独验证 |
| JSON 设置导入 | **不适用** | 代码没有实现设置导入导出功能（`src/ui/options/` 下没有导入/导出入口，`platform/settings-store.ts` 只有存储层读写，没有 JSON 序列化给用户下载/上传的 UI），该子项目前无对象可测 |
| 完整备份 / 恢复 | **不适用** | 代码没有实现「完整数据备份」（对话、收藏、页面、快照、图片一并导出再导入），只有收藏单条/按页面/全部导出成 Markdown（`favorite-export.ts`），Markdown 导出是只读呈现，不是可恢复的备份格式，两者不应混称（规格原文要求） |
| “已存”对应成功写入 | 通过 | `favorites.test.ts`「成功后广播 favorite/changed」；e2e「工具栏「存」：落库后按钮变「已存」」只在事务提交后才回 `ok`（AR-17，事务提交后才显示已存） |

## 4. 结论

| 字段 | 内容 |
| --- | --- |
| 结论 | 核心持久化机制（写失败回滚、删除级联、blob 引用计数、快照过期、升级失败保护）**通过**；「空间不足」「加载解压缩原目录更新」「扩展重载」**未执行**（前者无用例覆盖，后两者需要手动真实浏览器操作，自动化环境不模拟）；「旧 schema 升级」只验证了机制本身，产品还没有真实发生过一次版本迁移，**不能等同于「已验证过真实升级」**；「JSON 设置导入」「完整备份」**不适用**（功能未实现） |
| 范围边界 | 按规格「核心持久化的恢复先测；完整收藏、搜索与导出按产品分期进入」：收藏的增删改查、搜索、导出本轮已经实现并通过测试（见第 0 节「已存对应成功写入」及 history/favorites 相关单测），超出了规格原定的「先测范围」，顺带记录在案 |
| 是否需要修订架构/需求 | 不需要；建议在下一轮明确「空间不足」的处理策略（是否需要与 `storageFailed` 区分开、是否需要提示用户清理）后补对应用例 |
| 复测版本及结果 | 待手动项（加载解压缩原目录更新、扩展重载、空间不足）执行后补 |
