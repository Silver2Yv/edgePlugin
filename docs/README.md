## 冲突时听谁的

1. 需求冲突 → `FINAL_PLAN.md`
2. 决策冲突 → `DECISIONS.md` 里编号最大的那条
3. 架构冲突 → `ARCHITECTURE.md`（以版本号最新者为准，顶部有变更记录）
4. 测试口径冲突 → `VALIDATION_MATRIX.md`
5. 其余文档都是过程材料，与上述冲突时以上述为准

## 维护规则

- **改架构**：升版本号，更新文末变更记录，同步受影响的需求条目。
- **改需求**：先在 `DECISIONS.md` 追加决策，再改 `FINAL_PLAN.md`；不要只改一边。
- **做完一项原型**：结果按 `VALIDATION_MATRIX.md` 第 5 节模板记录在 `原型验证/记录/`，不要写进架构文档；只有被实测校准的数值才回写 `ARCHITECTURE.md` 5.15 与需求文档第 9 节（这些数字是参考值，决策 081）。
- **新增文档**：放进对应阶段的目录，并在本文件「文件清单」加一行；过程稿放 `过程文档/`，不进主目录。
- **过时文档不要删**，移入 `过程文档/` 并在表里标「历史」。
