# 两个参考项目分析

> **状态：历史文档，源码结论仍有效。** 实现手法可继续参考（`ARCHITECTURE.md` 多处引用其结论）；需求与决策以 `FINAL_PLAN.md`、`DECISIONS.md` 为准。
> 依据：本地源码（`selectlingo-v1.1.0` 为构建产物、`sidebar-copilot-main` 为源码）+ 两个仓库 README。标注「代码确认」的结论来自源码阅读。

## 一、SelectLingo（划词译问 v1.1.0）

定位：划词翻译工具，附带「就选中内容追问」和备忘录。TypeScript + Vite，MV3。

| 模块 | 实际行为 |
| --- | --- |
| 划词工具栏 | 选中 ≥2 字、松开鼠标后在选区右下方弹出「翻·问·存·设」胶囊条；输入框/可编辑区不弹；页面一滚动就隐藏；Shadow DOM 隔离样式；每个按钮可在设置里关闭 |
| 翻译 | 页内卡片流式输出；选中的已是目标语言时自动反向翻译；同原文+同模型命中缓存；超过 5000 字先弹确认；`Alt+T`；右键菜单 |
| 问答 | 页内 420px 卡片多轮追问；**上下文只有选中文本**（system = 问答提示词 + 选中原文，无页面标题/URL/前后文）（代码确认）；只保留最近 6 轮；**点卡片外任意位置卡片即关闭**；会话自动存入侧边栏「问答」页，可在侧边栏继续 |
| 输出格式 | 提示词要求「纯文本、不用 Markdown」，界面按纯文本显示，代码块/表格/列表不渲染（代码确认） |
| 思考模式 | 设置里有 自动/开启/关闭（发送 `thinking:{type}` 字段，主要适配 DeepSeek V4）；**推理内容被丢弃**，界面只显示「思考中…」；全局一个开关，不能临时切换（代码确认） |
| 模型 | 6 家预设（DeepSeek/OpenAI/Kimi/通义/智谱/Ollama）+ 任意 OpenAI 兼容；可拉取模型列表下拉选；**问答可单独指定模型**；但只能配一套服务商（一个 Base URL + Key） |
| 备忘录 | 选中文字 / AI 回答一键保存，记录来源页；可搜索、编辑、导出 Markdown |
| 侧边栏 | 只是记录管理器：翻译历史 / 问答会话 / 备忘录三个 Tab；**不能发起新对话，也不读页面** |
| 其他 | 强制页面文字可选；偏好走 sync、Key 只存本地；首次安装引导；深浅色跟随系统 |

**优点**
1. 划词即出工具栏，操作路径最短，零学习成本。
2. UI 有统一设计规范，精致；Shadow DOM 不受网页样式干扰。
3. 成本意识好：长文确认、翻译缓存、轮数上限、翻译/问答分模型。
4. 收藏/备忘录形成闭环。
5. 工程规范（TS、单测、CI）。

**缺点**
1. 问答没有上下文，模型不知道这页在讲什么，解释容易断章取义。
2. 没有页面级能力：不能总结全文、不能自由对话。
3. 卡片「太脆」：点页面任何位置即关闭；滚动时工具栏消失；卡片固定宽度，不能拖动/缩放。
4. 纯文本输出，无 Markdown 渲染。
5. 思考模式只有开关，没有内容。
6. 不支持 PDF（Edge 内置阅读器内无法划词）和 canvas 文字。
7. 侧边栏功能弱，与页内卡片是两套割裂的体验。

## 二、Sidebar Copilot（v2.1.2）

定位：页面感知的 AI 对话侧边栏 + 浏览器 Agent（替用户点击、填表、拖拽、控制视频）。原生 JS，无构建步骤。

| 模块 | 实际行为 |
| --- | --- |
| 页面读取 | 打开面板时注入脚本，抽取标题/正文块/表格/链接/媒体状态/选中文字；**默认最多送 14000 字（可调 2000–60000），超出时保留开头 72% + 结尾 24%，中间砍掉**；只读顶层文档 |
| 对话 | 侧边栏聊天，流式输出、Markdown 渲染（表格、代码块带复制）、停止/重试；页面正文以「不可信数据」包裹放进 system prompt |
| 快捷提问 | 总结本页 / 这页在讲什么 / 提取行动项 / 解释选中内容 / 提取数据 / 翻译成中文，另有 3 个 Agent 类 |
| 选中引用 | 面板底部「已引用选中内容 N 字」，可 × 取消 |
| Agent 操作 | 约 25 个工具：点击、输入、勾选、拖拽、滚动、开标签页、控制视频、CDP 截图/真实键鼠/上传文件；危险动作强制确认，不碰密码字段；**默认开启**；需要 `debugger` 权限 |
| 历史 | 多会话，切换、删除、导出 JSON，可关自动保存 |
| 其他 | 语音输入、中英界面、自定义背景色、深色模式、DeepSeek Harness 桌面端双向同步（需本地 Node bridge） |
| 入口 | 右键「解释所选内容」「总结此页」；`Alt+Shift+S`；工具栏图标 |

**优点**
1. 真正「读这一页」：选中内容 + 全页正文一起给模型。
2. 页面级能力完整：总结、提取数据/行动项、整页翻译、自由追问。
3. 对话体验完整：Markdown、代码复制、停止、重试、多会话。
4. 有提示注入防护意识。
5. 能力上限高（Agent）。

**缺点（含根因）**
1. 划词提问要右键 → 找菜单项，路径长。
2. **不支持思考模式**：请求不带任何思考参数，响应里的 `reasoning_content` 完全不处理；思考型模型推理期间界面空白干等，推理内容丢失（代码确认）。
3. **引用不更新的根因**：没有常驻的划词监听，选中内容只在「打开面板 / 切换标签页 / 页面加载完成 / 点刷新」时读取一次；发送时只有标签页变了才重读。所以同页换选一段，引用仍是旧的（代码确认）。
4. **`Alt+Shift+S` 小窗其实是 bug 的副产物**：快捷键处理里先 `await` 查询标签页再调用 `sidePanel.open()`，浏览器判定已不是用户手势而拒绝打开侧边栏，于是走兜底逻辑弹出 430×760 的独立窗口，装的是同一个侧边栏页面（代码确认 + Stack Overflow 已知问题）。所以小窗只是侧边栏布局被塞进窗口，不好看；面板里也根本没有模型选择器（只能在设置页改，同一时间只有一个模型）。右键菜单入口同样先 `await` 存储再打开，大概率也落到小窗。
5. 「有上下文」在长文里不成立：中间部分被砍掉，若选中段落在文章中部，它周围的内容反而送不到模型。
6. 一个对话贯穿所有页面：换页后旧对话还在，需手动新建。
7. 功能偏重、偏离阅读场景：Agent/CDP/桌面同步占大量代码和权限；`debugger` 权限使用时浏览器顶部会出现「正在调试」提示条。
8. 同样不支持 PDF。

## 三、对比总表

| 维度 | SelectLingo | Sidebar Copilot | 新插件初步方向 |
| --- | --- | --- | --- |
| 划词触发 | ✅ 自动工具栏 | ❌ 右键菜单 | 保留 SL 工具栏 |
| 划词问答上下文 | ❌ 仅选中文本 | ⚠️ 全页但长文砍中段 | 待定 |
| 页面总结 / 自由对话 | ❌ | ✅ | 保留 |
| 思考模式 | ⚠️ 有开关无内容 | ❌ | 待定 |
| 模型切换 | ✅ 翻译/问答分模型，单服务商 | ⚠️ 单模型，面板内不能切 | 待定 |
| Markdown 渲染 | ❌ | ✅ | 保留 |
| 翻译 | ✅ 专门优化 | ⚠️ 只是一个快捷提问 | 待定 |
| 收藏 / 笔记 | ✅ 备忘录 | ❌ | 待定 |
| 历史 | ✅ 分类记录 | ✅ 多会话 | 保留 |
| 悬浮小窗 | ❌ | ⚠️ 意外产物 | 保留并正式设计 |
| Agent 操作页面 | ❌ | ✅ 很重 | 待定 |
| PDF | ❌ | ❌ | 待定 |
| UI 观感 | ✅ 精致 | ⚠️ 一般 | 以 SL 风格为基准 |
