> 日期：2026-11-14
> **状态：历史评审，已全部处置。** 对象是 `ARCHITECTURE.md` v1.0（现行为 v1.2）。26 项发现的处置见 [`REVIEW_RESPONSE.md`](./REVIEW_RESPONSE.md)；本文只保留原始论证与证据，不必先读。仍未关闭、需要实测的事项见 `REVIEW_RESPONSE.md` 第 6 节。
> 对象：ARCHITECTURE.md v1.0；FINAL_PLAN.md v1.3；DECISIONS.md 001–058。
> 定位：评审意见，不替代原架构，不把建议自动变成已批准的需求。
> 配套：[原型与验收矩阵](./VALIDATION_MATRIX.md)。  
> 证据口径：原文行号以本次评审时文件为准；[Sxx] 对应文末实际读取的官方资料。  
> 评审方式：产品与交互、实现与状态、浏览器平台、安全隐私、性能、测试与维护六个视角交叉检查。

## 1. 评审结论

**主技术栈可以保留，架构方向有合理基础，但 v1.0 尚不足以作为无需补充设计即可全面实施的规格。建议有条件通过选型，先修订关键契约，再进入有验收门槛的原型阶段。**

WXT、TypeScript、Preact、IndexedDB、markdown-it、KaTeX、Vitest 与 Playwright 没有发现必须整体推倒的选型问题。更大的风险来自运行时和产品契约：黑名单到底允许什么、冷启动时怎样选择界面、请求与页面版本怎样绑定、历史上下文怎样退出请求、后台中断怎样恢复，以及浏览器无法提供保证时产品如何准确表述。

两条优先结论：

- **先解决确定的矛盾，再验证平台的不确定性。** 黑名单同时“排除注入”和“照常注入”，并非原型能替设计者回答的问题；sidePanel 在目标 Edge 版本上的行为则必须实测。
- **不要把“列了一个原型”当作“已有可用退路”。** 非流式不能天然解决等待响应过久；缩短数据库检查点不能恢复已断的模型网络流；“以后加一个适配器”也不能代替协议和能力契约。

本报告列出 **26 项发现：17 项 P1、9 项 P2**。P1 表示在相关模块落地前必须关闭；不表示所有次要功能都阻塞核心原型。当前没有实现代码可供确认实际安全漏洞，故不宣称存在已经复现的 P0 漏洞。

建议保留的基础：

1. 小窗使用扩展来源 iframe，侧边栏复用对话界面。
2. 模型请求和任务协调由后台统一管理；界面关闭不主动取消任务。
3. 哨兵与阅读器分离，尽量减少未交互页面的常驻工作。
4. PageDoc 保留块结构和来源，支持上下文和原文回指。
5. 默认不联网搜索、不自动总结、不自动检查更新。
6. 禁用回答原始 HTML，禁止自动加载模型输出里的外链图片。
7. 模拟中转站、真实网页样本、真实 Chrome/Edge 分层验证。

### AR-01 · P1：黑名单存在三套互不兼容的语义

**证据。** 架构 L152 说被关闭的网站完全不注入；L158 又说“不弹工具栏”仍注入哨兵，且只能读取选中文字；L159 说“不读取页面内容”允许选区但小窗只能自由对话，哨兵负责宿主；L160 又说两级都靠注册排除。L263 再次说只能自由对话。需求 L216 的说明却是“不弹工具栏只是不打扰”；M5 在 L239 要求关闭/不读取的站点不持续注入。架构 L119–120 又把宿主分配给阅读器，而非哨兵。

**反例。** 用户只想在某文档站关闭自动工具栏，随后通过快捷键总结。如果按 L158 实现，会意外失去全文；若按 L152 排除所有脚本，L159 的常驻宿主又不存在。隐私站点新加黑名单但未刷新，已缓存全文和待发请求应如何处理也未定义。

**建议。** 形成唯一权限矩阵，分别定义自动注入、手动唤起、读取选区、读取正文、截图、缓存、模型建议。推荐“不弹工具栏”只控制自动 UI；“不读取”禁止正文，用户明确提交选区作为单独例外；禁止自动注入的网站按用户动作临时进入最小路径。若坚持所有关闭站点零常驻脚本，设计相应按需注入与销毁。隐私拒绝应立即在后台生效；“下次刷新生效”只用于彻底移除已有脚本的解释，不能推迟禁止发送。

**验收。** 对两级设置分别测试新开、已有、子框架、快捷键、右键、截图、待发请求、历史上下文和建议请求。被禁止的数据不能通过任何入口进入请求。此项是文档矛盾，不是浏览器待测项。

### AR-02 · P1：预热被错误当成点击前必然完成

**证据。** 架构 L170 写用户点击时均已就绪；L192 要在预热阶段完成降级判断；L392–393 的指标也依赖预热。快捷键、右键及刚进入页面立即点击并没有这段等待窗口。官方只确认 sidePanel.open 需要用户交互，不能据此推导任意异步链都保留激活，也不应把“任何 await 都必然失效”写成规范事实。[S03]

**反例。** 第一次划词后 30 ms 点“解释”，而后台尚未唤醒、iframe 尚未握手；稍后加载失败时，原始点击已结束。此时无法靠“预先知道失败”保证两次操作内落到侧边栏。

**建议。** 定义 smallWindowReady = unknown / loading / ready / failed；给每种入口明确决策。若两步上限优先，unknown 时可同步走最小侧边栏，并给准确的临时提示；若优先等小窗，则必须承认冷态等待及失败时可能需要一次额外点击。这一取舍要写清，不能同时承诺无等待、总用小窗、总能自动降级。失败缓存绑定页面及策略条件，设置过期/重试；一次偶发失败不能永久代表整个域名不可用。

**验收。** 无预热、后台休眠、快速点击、iframe 超时、网络忙、快捷键无选区六种状态均有唯一落点。分别记录冷态/暖态，不仅测预热成功路径。已有原型 2/10 需扩展此时序。

### AR-03 · P1：空闲保活不能作为所有超时的保证，非流式退路不对题

**证据。** 架构 L212 用每 20 秒 API 调用覆盖“首字节超过 30 秒”；L503 的退路包含“强制整段非流式”。官方将空闲 30 秒、单次事件/API 长处理和 fetch 响应到达超过 30 秒分开列出；API 调用重置空闲计时，不构成覆盖全部条件的公开保证。[S01]

**反例。** 中转站 45 秒才发送响应头。切换非流式不让响应头提前到达，甚至可能等待更久。另一个服务立即返回响应头但迟迟不输出内容，这又是不同情况，不能只按“首字节”混在一起测试。

**建议。** 分测延迟响应头、头已到但流静默、持续流超过五分钟、整段 JSON、系统休眠与浏览器退出。将保活降为针对正常空闲回收的实现手段；恢复契约是保留检查点并标记中断，不能宣称恢复同一条已断网络流。删除“非流式解决响应等待”这一无依据退路。若改 offscreen，需单独修订权限、合法用途、执行位置、消息协议和回收方式；它仅支持 runtime 扩展 API，也不能保证浏览器退出后继续执行。[S02]

**验收。** 模拟中转站记录是否真实收到了请求、何时发头/首内容/结束；扩展记录任务与断点。不能用开发者工具常开时的成功替代正常生命周期验证。原型 1/8 的退路须先改写。

### AR-04 · P1：单写入者不等于任务幂等与流式一致性

**证据。** 架构 L208–214 定义 Job、快照和检查点，但 L349–359 的协议没有请求幂等键、流序号、快照版本或终态规则；数据表也没说明持久化任务所有权与恢复扫描。

**反例。** 发送后端口断开，界面不知道后台是否已接单，重连重发导致再次计费；旧增量晚于新快照到达，文字重复；“停止”与完成回调竞争，把已停止消息改成成功；两个同页窗口同时发问，跨 await 竞争同一个任务槽。

### AR-05 · P1：类型校验和握手令牌不是完整授权

**证据。** 架构 L186 仅写“同一标签页”；L359 写运行时校验；L139 用 isTrusted 防伪造。官方明确内容脚本可信度低于后台，应限制它能触发的特权动作。[S04]

**验收。** 错标签页、旧 document、重复令牌、伪造会话编号、超大消息、非法消息类型均被拒绝且无副作用。保留 iframe 来源隔离的价值，但把“防点击劫持”改成有限防护声明；不能声称宿主无法操纵其外壳。

### AR-08 · P1：上下文上限、速度预算和覆盖率没有分开

### AR-09 · P1：自由参数与自动容错可能改变用户选择

**证据。** 架构 L281 允许自定义请求头和额外 JSON；L282 要求实际模型一致；L283 会学习怪癖；L291–302 自动移除参数重试，却没有优先级和作用范围。

### AR-10 · P1：网络目标分类缺少真实数据路径

**验收。** 模拟写失败、空间不足、升级中断、删除引用、过期和大历史集，数据不悄悄丢失，错误非模态可见。

### AR-18 · P1：秘密保护退路含糊，敏感输入只在部分入口过滤

**证据。** 架构 L331 启动时收紧 local；L517 的退路是“每次启动再收紧，并对 Key 单独加密”。官方确认 local 默认可被内容脚本访问，session 在浏览器重启/扩展更新等情况下清空；没有从这些资料得到“访问级别跨所有重启必定保持”的证明。[S05] L167 的过滤只明确出现在工具栏描述，而右键、快捷键、降级抽取与诊断也会处理输入。

**反例。** 如果权限有启动窗口，事后再次收紧无法追回已暴露值；若密文和解密材料同放可读位置，加密不能抵御同一读取威胁。右键 selectionText 的来源可能是可编辑区域，不能因为绕过了哨兵就绕过 M6。

**建议。** 原型验证权限的首次安装、重启、更新、恢复顺序；真实 Key 写入前完成访问隔离。需要退路时考虑把秘密存于扩展来源专用数据库/存储访问层，并明确威胁模型；不把本机保存等同于操作系统级保密。统一 SelectionPolicy，所有入口执行，来源不明时保守拒绝读取表单值。诊断对请求头、URL 查询、响应回显和复制内容统一脱敏；错误原文按文本显示并限长。

**验收。** 启动早期、后台休眠、扩展重载时内容脚本读不到 Key；密码、普通输入、contenteditable、只读代码 textarea 的行为分别符合契约；诊断中放入合成秘密验证无泄露，不使用真实秘密做日志样本。

### AR-19 · P1：侧边栏的打开、关闭与转接没有单一裁决者

**证据。** 架构 L199 让后台总 open、侧边栏同时 window.close；L438 在 open 之后才写待转接对话；L202 在工具栏出现时决定目标。Chrome 官方有 close/open 及 windowId/tabId 的差异，但不保证这两个监听器的竞态结果。[S03]

**反例。** 已打开时后台 open 与页面 close 先后不同，可能闪烁或重开；新打开的侧边栏在待转接状态写入前订阅错误对话；多个窗口各有侧边栏时，同一快捷键被错误作用到其他窗口；工具栏出现后用户关闭侧边栏，点击仍发向旧目标。

**建议。** 开关由唯一协调路径裁决，窗口范围明确；在不能同时保证激活与查询的版本上，宁可公开支持“打开/聚焦”及显式关闭，也不要把竞态写成确定开关。若必须保留切换语义，原型证明后再定实现。转接使用 handoffId、windowId、tabId、conversationId 与确认消息；快速打开不依赖等待存储，但侧边栏初始保持待绑定状态，不先订阅默认对话。仅在订阅成功后收起小窗。

**验收。** 单窗/双窗、已开/关闭/被其他面板替代、后台冷启动、快速双击、切换标签页及转接中继续流式均无错窗串答。141/142 与目标稳定版分别验证；Edge 需单独结果。已有原型 13 要检查竞态，不能只看能否调用成功。

### AR-20 · P2：“轻量快速”缺少端到端与资源基线

**证据。** 架构 L389–395 测 gzip、局部主线程和暖态；L190 允许隐藏 iframe 长驻；L147 所有框架注入。L29/45/180 的“不卡网页/不占线程”描述过强。

**反例。** 30 个标签页各选过一次，隐藏 iframe、页面模型和端口累积；页面有 40 个框架；抽取为了判断“是否变化”先扫描全文；连续 50 ms 时间片仍造成滚动抖动。UI 不在宿主同一个 JS 执行环境，仍会争抢 CPU、内存和合成资源。

**建议。** 分无交互、选区未点击、冷启动、暖启动、长文、滚动、后台多任务、多标签页七类测量；记录 p50/p95、最长主线程任务、峰值/稳定内存、后台唤醒、消息字节数、首个有用回答时间。PageDoc 缓存和隐藏 iframe 设置按字节/实例数的回收上限，预热可取消。50 ms 应视作单任务上限风险，不应成为正常切片目标。数值由原型实测校准，不在评审里伪造通过标准。

**验收。** 与禁用插件基线对照，连续使用后资源可回落；没有点击工具栏时不产生模型请求。框架体积达标不能单独判 J6 通过。

### AR-21 · P2：前缀总结与答案来源提示需要准确表达

**证据。** 架构 L255 从头截取；L434 缓存总结直接展示；L313 通过提示词要求区分原文和自身知识。需求已经允许前缀截取，因此这不是要推翻用户已定策略。

**反例。** 关键结论在文章末尾，却把前 15% 的结果称为“本页总结”；模型标注“原文说明”但并无支持片段；实体命中只是同名词而非相关解释。提示词不能确定性证明答案来源。

**建议。** 部分读取时在结果标题/说明中明确范围，不能只在远处折叠区写百分比；提供读取更多或分块总结入口（其功能按原分期）。来源引用仅允许来自已发送块；把“已找到支持片段”与“模型声称来自知识”区别呈现。原文无答案、仅间接说明、同名实体和反事实年份进入评估集。

**验收。** 两个经典场景既测速度也测正确性：1927/1934 的证据在远处、只出现一次、重复实体和完全未说明；长文结论在尾部时不能给出无范围限定的全文概括。指标分别是证据召回、错误引用率、诚实承认缺失的比例。

### AR-22 · P2：分期依赖和完成标准仍不一致

**证据。** 架构 L534 把最小侧边栏加进核心，但需求 L344–346 仍写侧边栏随后、待用户决定；架构 L495 要核心块锚点，L534 模块清单未显式列出；黑名单到 L535 才做，却是 M 原则的实现基础。需求 L343–344 的“核心闭环”本来就没有“存/导出”，与 L317 的口号不一致。架构 L346 把 K6 扩成完整 JSON 数据备份，而需求 L270 的 K6 仅为设置导入导出。

**建议。** 下一版列“核心试用版”与“首期完整产品”各自验收，明确最小策略执行层、页面身份、块锚点、任务恢复属于前置依赖。最小侧边栏已确认，不再问是否需要。自定义动作编辑器可后做，但“总结本页”的固定入口需首版存在。完整数据备份是合理候选，不能冒用设置备份编号自动扩大首期。

**验收。** 每条阶段验收均有实现模块、数据依赖和测试归属；用户从新页面能在约定步数内触发总结，不要求先选中无关文字或自行绑定未预设快捷键。

### AR-23 · P2：输入焦点与阅读位置不是附属细节

**证据。** 架构 L166 基于鼠标松开定位只读输入选区；L188 的拖动替代方案可能改变输入层级；L203 通过滚回视口块保持位置。焦点、中文输入法、Tab、Esc、选择回答及屏幕阅读器没有契约。

**反例。** 键盘选词没有鼠标位置；用户正在写问题，新划词立即替换引用但未察觉；生成时自动滚动打断选中文本；侧边栏缩放网页后强制滚回段落顶部，反而改变原来的阅读行。

**建议。** 明确输入草稿、当前引用和请求快照三个状态。中文组合输入期间 Enter 不发送；Tab 有可预期焦点路径；Esc 只关闭当前层，不丢草稿；关闭后焦点返回触发位置。阅读锚点保留段内偏移，不仅块编号；异步校正不得覆盖用户刚发生的主动滚动。流式播报节制，不逐 token 通知屏幕阅读器。

**验收。** 键盘-only、中文输入法、200% 缩放、系统深色、高对比、生成中复制与划词、侧边栏开合时阅读位置均覆盖。

### AR-24 · P2：已有测试分层方向正确，但证明能力被高估

**证据。** 架构 L82 将页面抽取等整体称为纯逻辑；L473 让 Playwright 覆盖主路径、正式浏览器手工冒烟；L533 说 15 项原型完成即弃。

**反例。** 模拟 DOM 的单测通过，但真实 computedStyle、Selection、iframe 焦点、Popover、权限和用户激活失败；开启 DevTools 的后台不按真实用户场景回收；只测最新 Chromium 无法证明 Edge 141 承诺。

**建议。** 用纯数据单测验证装配、预算、协议和锚点算法；用真实浏览器 fixtures 验证抽取、布局和安全交互。关键原型保留可重复的测试壳、版本与证据，丢弃临时代码即可，不丢验收资产。最低支持版和稳定版分别记录，企业策略环境单列。禁止让 CI 绿灯自动升级“公司中转站可用”的状态。[S14]

**验收。** 每项结果能指向浏览器版本、环境、输入、步骤、日志及失败退路；未测标“未测”。详见配套矩阵。

### AR-25 · P2：上手和诊断过度依赖理想兼容行为

**证据。** 架构 L285 首期仅 Chat Completions；需求 L225 的选择器同时列 Claude、Gemini 等服务。L309 在最小对话后拉模型列表；L305 将“200 但不出字”判为流式被拦。L293 自动探测 /v1 也未定义候选范围。

**反例。** 中转站支持聊天却禁用模型列表；原生服务并不提供该 Chat Completions 入口；200 静默可能是推理、排队、缓冲或卡住；模型名尚未选择，最小对话用哪个模型也不明确。

**建议。** 向导按实际支持协议显示服务预设，原生未支持时写明兼容入口前提。模型发现失败可手填，不否定已成功的对话请求；明确先选/填测试模型。网络诊断按“已观察事实→可能原因→下一步”展示，不凭单个现象断言原因。URL 探测只在用户配置来源内有限尝试，不上传真实页面内容；不将鉴权信息放进打开的新标签页 URL。webRequest 结果与本次请求关联，缺证据时保留未知。

**验收。** 无模型列表、反向代理子路径、自定义完整地址、认证重定向、200 HTML、延迟头、静默思考、流被缓冲分别得到不同且诚实的提示。

### AR-26 · P2：手动发布需要验证版本、迁移与恢复

**证据。** 架构 L69–85 只有系列版本或“当前 LTS”；L474 发布 zip；L549 固定扩展 ID；L344–346 涉及永久数据与备份。固定 ID 有助于身份稳定，但不是重装后保留数据的保证，原文已承认卸载清空。

**建议。** 固定并记录实际测试的 WXT、Preact、Signals、Vite、TypeScript、Node、pnpm、浏览器范围，提交 lockfile。CI 包括独立类型检查、导入方向约束、生产构建产物和权限差异检查。为旧数据库升级、新旧配置、原目录替换更新、扩展重载及卸载重装分别写步骤。回退先考虑 schema 兼容，不承诺旧代码可读任意新数据库。JSON 导入要版本校验、大小限制、未知字段处理；导入网络连接配置后不自动发请求。

**验收。** 使用发布 zip 在干净 profile 安装，旧版本数据升级后仍可用；失败可从已验证的导出恢复。更新检查失败不影响阅读，默认关闭自动检查时无周期性更新请求。

## 5. 建议补入下一版架构的最小契约

不需要重画整套架构。优先补以下六张表或短规格：

| 契约 | 必须回答 | 对应发现 |
| --- | --- | --- |
| 站点权限表 | 自动注入/选区/正文/截图/缓存/历史/联网分别是否允许；何时生效 | AR-01、07、10、14、18 |
| UI 路由状态表 | 冷启动、预热中、失败、侧边栏已开/未知、多窗口时如何落点 | AR-02、19、23 |
| 任务状态与消息表 | 接单、重复、开始、检查点、停止、完成、中断、重试、快照与增量顺序 | AR-03、04、05 |
| 页面与请求身份表 | pageKey、documentId、contentVersion、selectionRevision、contextSnapshotId 的职责和失效条件 | AR-06、07、14、15、16 |
| 网络与模型能力表 | 实际接收方、发送内容、重定向/凭据、参数合并、能力未知和重试 | AR-08、09、10、25 |
| 阶段验收与数据表 | 核心/首期边界、schema 升级、删除、过期、导出、性能与实测门槛 | AR-17、20、22、24、26 |

建议的请求记录至少能回答“这次是谁、从哪一版页面、按什么范围、发给谁、有没有重试”：

~~~text
RequestRecord
  requestId / jobId / attemptId / conversationId
  source: windowId + tabId + frameId + documentId
  pageKey + contentVersion + selectionRevision
  contextSnapshotId + includedBlockIds + contextPolicy
  connectionId + interfaceType + effectiveModel + effectiveOptions
  inputEstimate + outputReserve + coverageDescription
  state + revision + createdAt + terminalReason
~~~

这是字段职责示意，不要求新增大而全的框架、事件总线或通用平台。可将相关字段放入现有消息/任务/快照记录，通过少量事务维护。

## 6. 开工顺序与门槛

1. **先修规格。** 关闭 AR-01 的矛盾，明确 AR-02 的 unknown 落点、AR-03 的失败契约、AR-06/07 的数据身份与发送范围。
2. **做一个贯穿真实链路的测试壳。** 一种连接、一段选区、最小小窗/侧边栏、真实后台请求、检查点、一次可靠原文锚点。这样能同时暴露路由、生命周期和数据身份问题。
3. **用模拟服务先打失败路径。** 冷启动、延迟头、断流、重试、转接、页面变化与拒绝读取，先保证不串数据、不重复发问。
4. **再做公司网络与浏览器矩阵。** 公司中转站仍由有访问条件的用户验证；提供脱敏的结果模板和测试包，不要求在聊天里贴 Key。
5. **根据证据决定抽取和预算。** 相同页面集公平比较自研与混合方案，并用冷/暖态和多标签页测量校准预算。
6. **按阶段补齐产品。** 截图、联网、完整历史等进入各自模块前关闭对应 P1，不能因“次要”而略过其安全契约。

完整步骤和通过条件见 VALIDATION_MATRIX.md。通过原型意味着相应风险获得证据，不意味着所有首期功能已经验收。

## 7. 真正需要产品决定的事项

其余技术细节可由实现者按本报告闭合；以下取舍会改变用户感受到的承诺，应在修订架构时明确记录：

| 事项 | 本次推荐 | 需要明确的代价 |
| --- | --- | --- |
| 黑名单两级 | 不弹工具栏只抑制自动打扰；不读取禁止正文；主动选区是显式例外 | 需统一 M5 与按需注入/销毁的表述 |
| 小窗冷态 unknown | 两步上限优先时同步使用最小侧边栏；小窗就绪后按正常路由 | 首次可能进入侧边栏，不能说一定是网站不支持 |
| 降低上下文档位 | 当前请求移除旧全文；历史含原文时明确提示或新对话 | 会影响连续对话语境；已经发送的数据无法收回 |
| 侧边栏快捷键 | 真正切换需原型通过；不通过则明确降级为打开/聚焦加显式关闭 | 不能在没有证据时同时承诺 141 双浏览器与完整切换 |
| 核心版本命名 | 核心试用版与首期完整产品分开验收 | “问答跑通”不等于“问→存→导出”已经交付 |

这些是评审建议，不在本轮改写原需求或默认替用户作最终选择。
