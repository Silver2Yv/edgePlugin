## 2. 逐条说明

### AR-01 黑名单三套语义

**采纳。** 这是文档的真矛盾，不是待测项。v1.0 有四处说法不一致：完全不注入、照常注入、只读选区、两级都排除。新表（4.1）把三级站点 × 九项能力列全，并明确：

- 「不弹工具栏」**只关自动 UI**，不关读取——这符合需求原意「只是不打扰」，也修正了 v1.0 第 11 节第 13 条写反的地方。
- 「不读取页面内容」**禁正文、禁缓存、禁建议**；用户主动选中的文字是唯一例外。
- 两级都**不常驻脚本**；快捷键与右键按需注入，满足 M5。
- **策略立即生效**，脚本移除在下次加载生效——两者分开说，不能拿「刷新后生效」拖延隐私拦截。

新增决策 059。

### AR-02 预热被当作必然完成

**采纳并改写成状态机。** 原文「点击时均已就绪」确实不成立：快捷键、右键、刚进页面立刻点击都没有等待窗口。新设计区分四个状态，并**明确取舍**：

- 优先保证「不吞掉问题、不丢点击」：unknown / loading 时当场显示骨架，加载结果决定后续。
- 结构性失败（网站策略）→ 同步转侧边栏，仍在用户手势内；偶发失败 → 本次转侧边栏。
- **承认代价**：冷启动首次可交互可能超过 200 ms；偶发失败时可能要再点一次。这写进第 11 节第 14 条与第 12 节。

新增决策 060。

### AR-03 保活与超时退路

**采纳。** 原文把「每 20 秒调接口」当成能覆盖「首字节超过 30 秒」，这是把三条回收条件混成一条。已改：保活只针对空闲回收；响应头超时、单事件超长以**检查点 + `interrupted`** 为契约；**删除「改非流式解决响应等待」**这条无依据退路。offscreen 不擅自引入，若原型证明必须，按新决策加权限与协议。

### AR-04 任务幂等与流式一致性

**采纳并写成状态机。** 补 `clientRequestId`、`jobId`、`attemptId`、`revision`、`seq`；接单先落库再发请求；快照带高水位、旧增量丢弃；终态不可覆盖；后台启动扫描未终结任务。

**并发发问**这一条我选了第三种：**不排队、不自动停止，改为输入框在生成中只提供「停止」**。理由是隐式排队会让用户以为新问题在等，自动停止会丢掉正在生成的半段。代价是多一次操作，已写入决策 062。

### AR-05 校验不是授权

**采纳。** 新增「发送者 × 消息 × 作用域」表，身份一律取自 `sender`；令牌 128 位、一次性、60 秒、绑定文档；握手前不订阅、不读秘密、不发请求；消息体积上限。

同时**收窄了 M7 的措辞**：能保证「网页脚本读不到对话内容」，**不能**保证「网页无法遮挡、移除或改变小窗外壳」。这是评审说得对的地方，原文的说法过强——被遮挡的小窗用户看得见，但技术上拦不住。

### AR-06 页面身份混淆

**采纳。** 拆成五个身份：`pageKey`（归档）、`documentId`（授权）、`contentVersion`（内容指纹，用块文本摘要哈希，不用长度）、`selectionRevision`（选区）、`contextSnapshotId`（请求快照）。缓存键包含内容版本；旧总结保留但标注「基于旧版本」；在途任务冻结原版本。

### AR-07 降档后旧全文仍被发送

**采纳。** 每次请求产出 `RequestContextPlan`；降档时**移除先前请求的页面全文**；历史里含原文时界面必须提示或建议新对话；换连接时重新计算接收方与预算；新选区不改写在途请求。这一条影响很大——它意味着「同页连续追问」在切到「只看选中」后语境会变短，已写进第 12 节。

### AR-08 预算混用

**采纳。** 拆成模型硬上限、输出预留、速度软预算、总结读取四分量；总结读取的百分比同时给出**占可提取正文的比例与字数**；覆盖率的「可提取正文」不等于整个网页；粗估留余量、不把一次校正当精确值。

### AR-09 参数合并与人工学习

**采纳。** 新增受保护 / 可覆盖 / 语义敏感三类；`model`、`messages`、`stream` 不可被额外 JSON 覆盖；能力学习绑定「连接 + 接口 + 模型 + 配置版本」；自动重试仅一次且仅在收到内容之前；**不得静默去掉会改变行为的字段**；未知能力显示为未知。

### AR-10 网络目标分类

**采纳。** 请求分类表列出六类：模型、搜索 API、抓取 API、页面图片、更新检查、直接抓取任意网址（不做）。每类写明发起环境、接收方、发送内容、凭据、目标限制。明确区分：**请求域名可见 ≠ 外发内容可见**；搜索只发查询词；模型凭据不与图片域名混用；跨主机重定向不继承自定义头。

### AR-11 渲染安全

**采纳。** 引用从 AST 生成、属性单独赋值、只接受本次请求的编号；KaTeX 关 trust、限展开与尺寸、宏不跨消息；代码高亮限长限语言；CSP 与协议白名单；超长截断并提示。不加通用净化库，理由是最终 HTML 由我们自己生成（评审也提到「是否叠加由路径决定」）。

### AR-12 已完成块永久冻结

**部分采纳。** 接受「后置引用定义会前向影响」这一事实。方案不是自研通用增量解析器，而是：**限定支持的语法**；已完成块用稳定 key 保留；**结束时做一次完整校正**，只替换受影响块；用户正在选中的块延迟替换。这与评审建议一致，只是明确了不做的事。

### AR-13 抽取规则与折叠内容矛盾

**采纳。** 原文「读手风琴、又不读 `hidden`」确实是同一类元素。改为先定语义容器、再定样式启发式，冲突时按语义容器判读；新增「上下文单元」定义，让「前后 3 段」不会退化成「3 行代码」；实体回指明确为启发式，按证据召回验收。

同时**删掉了对 Readability 的绝对判断**：它支持自定义 serializer 返回 DOM（S11），所以「库必然丢位置」不成立。抽取方案改为 V-08 公平比较后再定。

### AR-14 iframe 缺少归属与合并

**采纳。** 选区消息绑定 `frameId + documentId + selectionRevision`；优先读选区所在文档；是否合并多个框架必须显式，不自动把广告/登录框汇进全文；子框架策略按顶层与来源取更严；右键优先用浏览器给的 `selectionText`。

### AR-15 编号必须绑定快照

**采纳。** 引用身份改为 `contextSnapshotId + contentVersion + blockId`，只在该请求发送过的块集合内有效；模型编造编号不可点击；被引用快照不随定期清理过期；近似匹配设歧义门槛，「能定位」与「支持结论」分开评价。

### AR-16 截图抓的是调用时的活动页

**采纳。** 绑定窗口、标签页、文档、视口版本；截图前后核对，状态变了就丢弃；隐藏遮罩与小窗后再截、等两帧；按实际图片尺寸换算坐标；**预览并确认后才发送**。明确「未读取输入值 ≠ 图片里没有敏感内容」。

### AR-17 存储闭环

**采纳。** 「已存」以事务提交为准；定义级联与引用计数；过期清理跳过被引用与进行中的任务；schema 升级有事务、样本与失败处理；搜索先缩小集合、分页、可取消。

### AR-18 Key 与敏感输入

**采纳。** `SelectionPolicy` 在所有入口统一执行；Key 写入前先确认存储已收紧，未确认不落盘；后台每次唤醒重新收紧；威胁模型如实写明「本机保存 ≠ 操作系统级保密」；诊断对象统一脱敏。

### AR-19 侧边栏双端竞态

**部分采纳 + 待实测。** 原文让后台 `open()`、面板 `window.close()`，确实是双主。但需求 J4 想要一键开关，所以不能简单放弃。折中方案是**把「切换」降为有条件能力**：`open()` 同步发出，面板收到带时间戳的事件后自行判断是否关闭；V-11 证明不了就**公开降级为「打开/聚焦」**，并在需求上同步改写。**没有证据就不承诺。** 转接改为握手式：订阅成功后才收起小窗。

新增决策 061。

### AR-20 性能缺端到端基线

**采纳。** 5.15 增加资源上限（隐藏 iframe 数量、PageDoc 缓存、消息大小）；测量场景扩展到无交互、多框架、30 个标签页、长回答；记录 p50/p95、最长主线程任务、内存回落；50 ms 改为「风险上限」而非切片目标；明确「框架体积达标不能单独证明 J6」。

### AR-21 总结与来源的可信度

**采纳。** 覆盖范围写在**结果标题处**，不只写在远处小字；来源把「找到支持片段」与「模型声称来自知识」分列；引用只允许来自已发送块；验收增加「结论在尾部」「实体只出现一次」「同名实体」「原文完全不说明」四类反例。

### AR-22 分期与验收不闭环

**采纳。** 第 10 节改为「核心试用版」与「首期完整产品」两套口径；五项前置依赖（权限矩阵、页面身份、块锚点、任务恢复、固定总结入口）写进核心版；**K6 收窄为只含设置**，完整数据备份单列为新增能力（不冒用编号）。需求文档第 8 节的表格没有在工作区，需要你或下一轮把它对齐——这一条只改在架构侧。

新增决策 063。

### AR-23 焦点与阅读位置

**采纳。** 阅读锚点保留块内偏移；异步校正不覆盖用户刚发生的主动滚动；V-12 覆盖键盘、中文输入法、Esc、缩放、深色、生成中复制。

### AR-24 测试证明力被高估

**采纳。** 单测只证明纯数据逻辑；抽取、布局、选区、权限在真实浏览器验证；远端 Chromium 通过不能替代真实 Chrome/Edge；原型保留测试壳与样本；**未测就标「未测」**。

### AR-25 上手与诊断过度自信

**采纳。** 诊断按「已观察事实 → 可能原因 → 下一步」呈现，不凭单一现象断言原因；模型列表失败可手填、不否定已成功的对话；测试模型先选定；URL 探测只在用户配置内，不在新标签页 URL 里放鉴权信息。

### AR-26 发布与迁移

**采纳。** 锁定并记录 WXT、Preact、Signals、Vite、TypeScript、Node、pnpm 的实测版本与 lockfile；CI 含独立类型检查、依赖方向、构建与权限差异；旧库升级、原目录更新、重载、卸载重装各有步骤；JSON 导入做版本与大小校验，导入连接后不自动发请求。

## 4. 我不同意的两处措辞

1. **「不要为框架体积把 Preact 当成性能保证」**——同意，原文确实把「5 KB」和「不卡网页」写得太近，已改。但结论仍是保留 Preact：换框架带来的差别远小于「不在网页主线程渲染」和「按需注入」。
2. **「退回纯 Vite 是零成本」**——评审批评得对。原文「必要时退回纯 Vite」写成了无成本退路，已改为「应急手段，不是零成本选项」，并补上「锁定完整版本与 lockfile」。

## 5. 评审没点、但我自查发现的一处

`K6` 在需求里是「设置导出导入」，v1.0 写成了「完整的 JSON 备份与恢复」，扩大了首期范围。v1.1 已收窄，并在第 11 节写明完整数据备份是另一个能力。
